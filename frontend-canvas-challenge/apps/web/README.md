# Канвас (`apps/web`)

Фронтенд на React 19, Vite 7, React Router 7 и `@xyflow/react` 12. Бэкенд не менялся. Авторизации нет.

## Запуск и сборка

Из корня репозитория, Node.js 24.x и npm 11.x:

```sh
npm ci
npm run dev
```

Канвас: http://127.0.0.1:5174/. API: http://127.0.0.1:4001/. Swagger: http://localhost:4001/docs/.

Отдельно: `npm run dev:api`, `npm run dev:web`. Сборка: `npm run build`. Только фронтенд: `npm run build -w @canvas/web`.

Адрес API — `apps/web/.env` (`VITE_API_URL`, см. `.env.example`).

## Клиент API

У canvas **нет** обёртки `{ data }`. Тело ответа — сам ресурс. Клиентский тип `ApiResult` — это статус, ETag, Location и Retry-After плюс тело, не envelope магазина.

| Слой | Файл | Что менять |
| --- | --- | --- |
| Базовый URL | `api/config.ts` | `VITE_API_URL` |
| Заголовки и `fetch` | `api/http.ts` | `If-Match`, `Idempotency-Key` |
| JSON / 304 | `api/parse.ts` | пустое тело, битый JSON |
| Ошибки `{ error }` | `api/errors.ts` | `mapError`, `MESSAGES` |
| Методы | `api/resources.ts` | одна строка на новый путь |

Компоненты получают данные или `userMessage`. Ноды не ходят в `fetch`.

## Debounce и очередь PUT

`lib/save-queue.ts`: пауза 500 мс (из `GET /api/config`), правки сливаются в один `queued`, PUT одного графа идут строго по очереди. Снимок всегда из refs через `toApiGraph` — служебные поля React Flow (`selected`, `dragging`, `measured`) не уходят на сервер. `If-Match` — ETag **с кавычками** из заголовка GET/PUT. При 412 очередь `pause()`, локальный черновик остаётся, кнопка перечитывает сервер. Генерация сначала `flush()`, при ошибке сохранения не стартует.

## Обработка графа (P1)

Горячий путь — `indexEdges` + `canConnect` и `toApiGraph`.

- **Когда:** каждый drag-connect (`isValidConnection` / `onConnect`), каждый PUT (debounce и flush перед генерацией). Лимит API — 20 нод и 20 рёбер.
- **Проходы:** один `for` по рёбрам → два `Set` (вход занят, выход генератора занят). Lookup ноды — `Map` за один проход. `toApiGraph` — один проход по нодам и один по рёбрам, в запрос только `id/type/position/data` и `id/source/target`.
- **Память:** плотные массивы через `push`/`slice`, без `.map().filter()`, без `delete` по индексу массива. `updateAt` копирует массив только если элемент реально изменился; остальные ссылки сохраняются.
- Превью генерации лежит в `data` result-ноды (на сервер не сериализуется). Обновление одной картинки не пересобирает контекст текстовых нод.

## Проверенные сценарии

- Создание space, три типа нод, UUID, текст и перемещение сразу на экране, reload открывает то же space.
- Связи только текст → генератор → результат; один вход; у генератора один результат; удаление ноды снимает рёбра.
- Debounce 500 мс, одиночная правка тоже сохраняется, быстрые правки → один PUT, If-Match актуален.
- Generate сразу после ввода: flush, затем POST generation, картинка в связанном result.
- Сценарий failure и повтор с новым ключом. Повтор после потери ответа — тот же Idempotency-Key.
- 412: черновик на месте, «Загрузить серверный граф».
- Reload во время processing продолжает опрос. Rewire/удаление цепи не подставляет старый результат и не оставляет вечный spinner.
- Unmount / смена space останавливает poll.

## Недоработки

- Нет слияния двух версий графа при 412 — только явная загрузка сервера, как в задании.
- Мобильная вёрстка канваса не оценивается.
- Автотестов фронтенда нет; `npm run smoke` проверяет API.
