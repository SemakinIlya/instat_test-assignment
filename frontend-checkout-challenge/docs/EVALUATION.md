# Как оцениваем решение

Каждое задание оцениваем по одной шкале: 100 баллов. У каждого пункта три оценки: **5** — работает целиком, **2** — работает частично, **0** — не сделано или не работает. К сниженной оценке записываем конкретный пример. Если проверку не удалось провести из-за нашей среды, оставляем её без оценки и возвращаемся к ней позже.

Ориентир — 6–8 часов. Начните с полного основного сценария, затем займитесь повторами, ошибками и восстановлением. Когда время закончится, пришлите сделанное и перечислите недоработки. Все пункты ниже нужны для сравнения решений; неполную работу тоже посмотрим.

## Основной сценарий — 40 баллов

| Пункт | Что проверим — по 5 баллов                                                                           |
| ----- | ---------------------------------------------------------------------------------------------------- |
| A1    | Каталог загружается из API; доступный товар попадает в серверную корзину.                            |
| A2    | Количество меняется, позиция удаляется, состав и итог корзины совпадают с API.                       |
| A3    | Можно заполнить контакты и выбрать оба способа доставки с нужными полями.                            |
| A4    | Смена товаров или доставки даёт новый расчёт; стоимость доставки и итог берутся из API.              |
| A5    | Заказ создаётся с выбранной оплатой. В форме карты используются название и маска из API.             |
| A6    | После запуска оплаты виден процесс ожидания. Успех определяется итоговым статусом заказа на сервере. |
| A7    | Страница успеха показывает номер, товары, доставку и сумму именно этого заказа.                      |
| A8    | Заказ с наличными завершается с сообщением об оплате при получении, без попытки онлайн-оплаты.       |

## Устойчивость — 30 баллов

| Пункт | Что проверим — по 5 баллов                                                                                                                                        |
| ----- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| B1    | Отказ и отмена оплаты различимы. После каждого можно оплатить прежний заказ новой попыткой.                                                                       |
| B2    | Двойное нажатие и повтор запроса после потери ответа не создают второй заказ или попытку. Для повтора сохраняются тело и ключ; новая попытка получает новый ключ. |
| B3    | Перезагрузка восстанавливает сессию, корзину и заказ. Незавершённая оплата отслеживается до результата.                                                           |
| B4    | При конфликте версии корзины или устаревшем расчёте данные обновляются, оформление можно продолжить.                                                              |
| B5    | Сбой сети или API не стирает форму. Понятно, как повторить действие; старый ответ не подменяет более новые данные.                                                |
| B6    | Пустую корзину нельзя оформить. Недоступный товар и превышение остатка обработаны. Опрос оплаты прекращается после завершения или ухода со страницы.              |

## Код — 10 баллов

| Пункт | Что проверим — по 5 баллов                                                                                                                                                                                                                    |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1    | Компоненты и типы можно понять без постоянных переходов по проекту. Данные API, состояние экрана и действия пользователя различимы; нет нескольких расходящихся копий одного правила.                                                         |
| D2    | Новый запрос можно добавить без копирования настройки соединения. Общие заголовки, отправку, разбор ответа и перевод ошибки в понятный вид можно менять по отдельности, без обхода всех страниц или нод. В README объяснено, где это сделано. |

Название подхода, число файлов и выбор библиотеки на оценку не влияют.

## Запуск и описание — 5 баллов

| Пункт | Что проверим — 5 баллов                                                                                                                                                                                            |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| E1    | Из свежего клона по README можно установить зависимости, запустить API и фронтенд, собрать приложение. Есть файл фиксации зависимостей, проверенные сценарии, известные недоработки и примерное затраченное время. |

Проверки можно описать вручную или автоматизировать. Баллы даём за подтверждённое поведение; количество тестов, коммитов или строк кода преимуществом не будет. Дополнительные функции, деплой и выполнение второго задания не добавляют баллов. Библиотеки и нейросети использовать можно; на встрече обсудим код и небольшое изменение в нём.

## Кого пригласим

Сначала смотрим работы от 75 баллов, с минимум 30 за основной сценарий и 15 за устойчивость. При этом основной путь до результата должен проходить целиком: приложение не должно показывать вымышленный успех или молча терять данные. При равном результате сравним сумму за основной сценарий и устойчивость, затем устройство кода, затем интерфейс. Если работы по-прежнему равны, пригласим обе или проверим их ещё одним рецензентом.

Это ориентир для отбора, а не обещание приглашения по числу баллов. Работы ниже порога разбираем отдельно по конкретным пробелам. Решения смотрим раз в три дня. Вариант задания и использованные инструменты на приоритет не влияют.
