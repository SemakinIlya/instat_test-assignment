# Магазин (`apps/web`)

Фронтенд на React 19, Vite 7 и React Router 7 (declarative `BrowserRouter`). Бэкенд не менялся.

## Запуск и сборка

Из корня репозитория, Node.js 24.x и npm 11.x:

```sh
npm ci
npm run dev
```

Магазин: http://127.0.0.1:5173/. API: http://127.0.0.1:4000/. Swagger: http://localhost:4000/docs/.

Отдельно: `npm run dev:api`, `npm run dev:web`. Сборка: `npm run build` (контракты + API + фронтенд). Только фронтенд: `npm run build -w @checkout/web`.

Адрес API задаётся в `apps/web/.env` (`VITE_API_URL`, см. `.env.example`). Cookies не используются.

## Как устроен клиент API (D2)

Новый запрос — одна строка в `src/api/resources.ts`. Страницы не вызывают `fetch`, не читают `Response` и не разбирают JSON.

| Слой | Файл | Что менять |
| --- | --- | --- |
| Базовый URL | `api/config.ts` | `VITE_API_URL` |
| Заголовки и `fetch` | `api/http.ts` | `Authorization`, `Idempotency-Key`, `Content-Type` |
| Тело / 204 / envelope `{ data }` | `api/parse.ts` | `readPayload`, `unwrapData` |
| HTTP → понятная ошибка | `api/errors.ts` | `mapError`, `MESSAGES`, `fieldErrors` |
| Методы ресурсов + токен | `api/resources.ts` | `api.*`, `setAccessToken` |

Токен гостевой сессии хранится в модуле `resources`, не в компонентах. `reportError` / `useActionError` только показывают уже разобранный текст и игнорируют abort. Состояние экрана (корзина, черновик, активный заказ) — `state/ShopProvider.tsx`. Epoch корзины отсекает устаревший GET после быстрого PUT. Ключи идемпотентности — `lib/storage.ts` (отпечаток тела → тот же UUID при повторе).

Типы ответов берутся из `@checkout/contracts` (`Static` схем), без второй копии правил.

## Обработка данных

В каталоге и корзине индексы `qtyByProductId` / `stockByProductId` собираются одним проходом (`lib/lookup.ts`), без `.find` внутри `.map`. Опрос оплаты — общий `pollUntil` (`lib/poll.ts`), не цикл в странице.

## Проверенные сценарии

- Каталог с API, доступный товар в серверную корзину, недоступный и сверх остатка заблокированы.
- Изменение количества, удаление, итог совпадает с API.
- Pickup и courier, quote с сервера, смена доставки/корзины даёт новый расчёт.
- Карта: название и маска из `/api/sandbox`, ожидание, успех только если заказ `paid` / `paymentStatus=succeeded`.
- Наличные: «Заказ оформлен, оплата при получении», без POST payments.
- Decline и cancel различимы, повтор того же заказа новой попыткой.
- Двойной клик оформить/оплатить не создаёт второй заказ/попытку (lock + Idempotency-Key).
- Reload восстанавливает сессию, корзину, черновик и недоплаченный заказ; poll продолжается.
- `CART_VERSION_CONFLICT` / `QUOTE_EXPIRED`: корзина обновляется, quote пересчитывается, форма не стирается.
- Пустую корзину нельзя оформить. Уход со страницы заказа останавливает опрос.

## Недоработки

- Условные запросы If-Match/ETag API в задании не требуются и не реализованы.
- Нет автоматических e2e-тестов фронтенда; проверка ручная и `npm run smoke` по HTTP.
- Мобильная ширина 390 проверена вёрсткой; отдельного набора жестов нет.

## Время

Ориентир задания 6–8 часов на основной путь, плюс доработка устойчивости, DRY и документации.
